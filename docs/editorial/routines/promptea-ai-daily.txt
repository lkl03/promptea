=== PUBLISHING ===
Dry run first with "dryRun": true and confirm HTTP 200. Fix any validation error and retry until it validates. Then resend with "dryRun": false.
Write the payload to payload.json and sign it:

cat > sign.mjs <<'EOF'
import {createHmac,randomUUID} from 'node:crypto';
import {readFileSync} from 'node:fs';
const SECRET=process.env.PUBLISH_SECRET;
const raw=readFileSync('payload.json','utf8');
const ts=String(Math.floor(Date.now()/1000));
const nonce=randomUUID();
const sig=createHmac('sha256',SECRET).update(`${ts}.${nonce}.${raw}`).digest('hex');
const res=await fetch('https://www.promptea.me/api/internal/blog/publish',{method:'POST',headers:{'content-type':'application/json','x-promptea-timestamp':ts,'x-promptea-nonce':nonce,'x-promptea-signature':sig},body:raw});
console.log(res.status, await res.text());
EOF
PUBLISH_SECRET='<the value of the PUBLISH SECRET line at the top>' NODE_USE_ENV_PROXY=1 node sign.mjs

NODE_USE_ENV_PROXY=1 IS REQUIRED AND NOT OPTIONAL. Node's built-in fetch does not read HTTPS_PROXY on its own, so without it the request leaves this VM outside the egress proxy and the gateway returns:

That message points at the allowlist, but the allowlist is FINE - the request simply never reached the proxy that reads it. If you see that 403, add the flag and retry; do NOT go and re-check domain or egress settings, and do NOT report a publication failure until you have retried WITH the flag. (Verified: identical payload returns 403 without it and 201 with it. Needs Node >= 22.21; this environment runs v22.22.x.) curl is unaffected and needs no flag.
The body you sign must be byte-identical to the body you send - always sign the exact file contents.
